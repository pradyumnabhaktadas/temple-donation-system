🗄️ Data Backup

A full backup of donor records, donation history, and every admin-editable lookup list (Campaigns, BACE, Festivals, Seva Types, Live To Give Purposes, Preachers), exported as a ZIP of CSV files. Admin login credentials and stored receipt PDFs are deliberately left out -- receipt PDFs can always be regenerated from a donation's own data, and login credentials shouldn't leave the database.

⬇ Download Backup Now

"Download Backup Now" streams a fresh ZIP straight to your browser and doesn't touch this server's disk. "Run Backup Now" does the full weekly-job routine on demand -- saves a copy to instance/backups/ on this server, prunes old ones beyond the retention limit, and emails it {% if smtp_configured and backup_email %}to {{ backup_email }}{% else %}(if SMTP is configured below){% endif %}.

The actual weekly run is backup_data.py, scheduled via the temple-weekly-backup Cron Job in render.yaml (Sundays, 2 AM UTC). That's a separate Render service with its own filesystem -- email is the durable copy of that automatic run (a Render disk can only be attached to one service, so it can't write into this web app's own storage). If your Render plan doesn't support Cron Jobs, run python backup_data.py weekly from any external scheduler instead (e.g. a free cron-job.org trigger, or your own machine's crontab).

♻️ Restore From a Backup

Reloads donors, donations and the lookup lists from a backup ZIP. Admin logins are never touched, so nobody's password changes. Preview first — it reports exactly what would change and writes nothing. Before any real restore, a backup of the current data is taken and saved automatically, so this is undoable.
